## Source inventory

The adjacent `inventory.json` records source commit, file hashes, route literals,
environment variable names, cookie literals and test entrypoints. It never reads
runtime environment files or user data. Generated by the infrastructure repository's
`bench/inventory.py`. The index is not an authorization proof: dynamic environment
names and Go subrouter prefixes require review in source. File hashes describe the
working source even when benchmark additions have not yet been committed.

## Storage and compatibility

SQLite WAL: links, counters, keys and persistent OIDC session/replay records. OIDC access tokens remain encrypted. Preserve 0.5.0 behavior and schema during the toolchain upgrade.

## Identity and privacy

Live UserInfo on each OIDC authorization, same sub and required current groups; fail closed on IdP errors. API keys need the owner's latest valid OIDC session and cannot gain group admin. Public redirects are independent; PIN protects preview too.

## Required workloads and failure cases

Redirect/CRUD at concurrency 1/5/10/25, current group removal, copied/expired cookie, rejected key, local/backchannel logout, durable replay rejection, IdP outage, restart, PIN and SQLite failure. Microbenchmarks must keep actual HTTP UserInfo calls enabled.

Run only with synthetic data, an isolated store and a test IdP where needed.
Do not redirect an existing suite at a production URL or mount production data.
Retain current suites before adding benchmark-specific checks; their script names
are listed in the generated inventory. Browser, API and persistent-state effects
must all be verified, not just HTTP success.

## Measurement contract

Three repetitions with fixed data and resource limits, alternating variant order:
cold start, five-minute warmup, ten-minute workload and ten-minute recovery.
Record container current/peak memory, CPU per operation, latency distribution,
throughput, errors and recovery. Do not equate heap allocations with container RAM.
A missing measurement or failed request cannot count as zero usage or success.
Full-load execution on a shared production host needs an agreed window and limits.
